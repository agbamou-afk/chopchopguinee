- Model: `marche_reputation_events` (immutable, append-only) + `marche_reputation_dimensions`. Both REVOKE ALL, RLS on with zero policies; every access path is a `SECURITY DEFINER` RPC pinned to `search_path=public`.
- Transaction kinds: `merchant_order` (completion = `status='committed'` AND `fulfillment_state='delivered'` AND `delivered_at` set), `procurement` (mission `state='completed'` AND `completed_at` set). Nothing earlier is rateable.
- Subject kinds: `merchant_store`, `delivery_driver`, `shopper`. Identity is resolved server-side by `_marche_reputation_resolve`; a client-supplied subject is refused `CLIENT_SUBJECT_NOT_ALLOWED`, a client-supplied aggregate `CLIENT_AGGREGATE_NOT_ALLOWED`.
- EXACT MISSION BACKLINK LAW (R9 closeout): `marche_orders.mission_id` alone is never trusted. A `delivery_driver` subject exists only when ALL hold: `m.id = o.mission_id` AND `m.ref_market_order_id = o.id` AND `m.merchant_store_id = o.merchant_store_id` AND `m.type = 'marketplace_delivery'` AND `m.state = 'delivered'` AND `m.courier_id IS NOT NULL` AND a real `profiles` row exists for that courier AND the courier is not the caller. Pickup / no mission / any single mismatch = no driver subject, while the store stays rateable. Fail-closed, never inferred.
- Authority: only the transaction buyer may rate, once per (transaction, subject), never themselves. Replay returns `ALREADY_RATED`; update/delete raise `REPUTATION_IMMUTABLE`.
- Public surface: `marche_reputation_summary` (anon-readable) exposes count, average and dimension averages only — no rater, transaction, mission, courier or comment. `marche_reputation_submit` / `marche_reputation_eligibility` are authenticated-only; `_marche_reputation_resolve` is not client-callable.
- Isolation: the same person rated as delivery driver and as shopper keeps two separate cohorts. Legacy `ride_ratings` and `driver_profiles.rating` are never written. No wallet, ledger, held, flag or R8 observation effect.
